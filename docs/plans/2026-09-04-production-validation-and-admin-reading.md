# XINGYU 下一阶段：生产验收与管理端阅读体验

**状态：** 当前授权范围已完成；Git 提交与推送按用户要求留作后续独立操作  
**日期：** 2026-09-04  
**前置版本：** `c1d473a`  
**线上站点：** `https://zhangwansen.click/`

## 1. 阶段目标

本阶段先把刚上线的 R2、缓存与资源拆分在真实生产环境中验收清楚，再优化管理端的阅读体验。

目标不是重新设计网站，也不是在管理端复制一套前台页面。公开端与管理端继续复用同一套首页、文章卡片、Markdown 渲染器和阅读器；管理端只增加权限范围、管理入口和必要的上下文提示。

完成后应达到：

1. 生产环境的附件上传、下载、图片变体和权限链路可验证、可监控。
2. 管理员可以像浏览公开博客一样浏览全部内容，并自然进入编辑、空间和文章管理。
3. 弹层阅读、独立阅读、翻页、目录、搜索、动画和阅读进度在前后台保持一致。
4. 管理端在桌面和移动端都能稳定使用，关闭阅读器后回到原来的筛选、空间和滚动位置。
5. 不降低公开站点性能，不泄漏草稿、私密空间、预览令牌或附件。

## 2. 设计边界

### 必须保持

- 保持现有暗色/明亮主题、岛式导航、留白、圆角和动效语言。
- 保持公开首页、文章、关于页面的整体排版与视觉比例。
- 继续复用 `BlogHomeExperience`、`ModalPostReader`、`PostPageView` 和 `MarkdownRenderer`。
- “浏览”是正式管理功能，不使用“预览”来命名管理端首页。
- 顶级文章与知识空间在信息架构上保持隔离；空间文章不得进入公开首页和文章归档。
- 管理端搜索必须覆盖顶级文章和空间文章，MCP 搜索能力保持可用。

### 本阶段不做

- 不重写编辑器或 Markdown 渲染器。
- 不改变文章公开 URL、稳定公开 ID、Slug 历史重定向和现有 MCP 契约。
- 不引入新的固定企业/团队/项目层级。
- 不为了性能删除 Mermaid、KaTeX、代码高亮或完整 Markdown 能力。
- 不大范围更换字体、配色、导航结构或首页排版。

## 3. 真实使用场景与验收标准

### 场景 A：生产附件闭环

**前置条件：** 管理员已登录，R2 `MEDIA` 绑定可用，存在一篇测试草稿。

**操作：**

1. 在文章编辑器上传图片和普通附件。
2. 保存草稿并在管理端阅读器打开。
3. 将一份测试附件关联到既有公开的 Markdown 示例文章（不修改正文），从公开路径访问；测试草稿始终保持未发布。
4. 使用有效私密预览链接访问空间文章或草稿附件。

**预期：**

- 原始对象写入 `xingyu-production-media`，D1 只保存必要元数据。
- 图片按视口返回合适尺寸的 WebP 变体，不出现拉伸、裁切错误或 CLS。
- 公开附件可以读取，但每次复用都必须重新进入权限检查；内容未变化时通过 ETag 返回 `304`。草稿和空间附件必须要求管理员身份或有效预览令牌，并返回 `private, no-store`。
- 无权限、过期令牌和不存在的对象返回明确的 401/403/404，不返回 500，也不泄漏对象键。
- MCP 上传、列出和下载附件与网页端遵循同一权限规则。

**可观察证据：** R2 对象、D1 附件记录、响应状态与缓存头、桌面和移动端截图、MCP 调用回执。

### 场景 B：管理端首页浏览

**前置条件：** 管理员已登录，顶级文章、草稿和空间文章均存在。

**操作：** 打开 `/admin`，在“浏览”中切换全部/公开/私密、分类，并打开文章。

**预期：**

- 默认展示与公开首页相同的视觉体验，但可以查看管理员有权访问的全部内容。
- 状态和范围提示轻量融入页面，不形成突兀的后台卡片。
- 公开、草稿、空间内容的身份标记清晰，但不抢夺文章标题的视觉层级。
- 点击文章使用共享弹层阅读器；关闭后恢复原筛选条件和滚动位置。
- “编辑”“文章管理”“知识空间”等管理动作存在，但不破坏阅读沉浸感。

### 场景 C：空间内浏览与返回

**前置条件：** 存在至少三级空间和多篇空间文章。

**操作：** 从空间树进入子空间，阅读文章，切换上一篇/下一篇，再关闭或返回。

**预期：**

- 面包屑显示完整空间路径，可快速返回上级空间。
- 上一篇/下一篇默认限制在当前浏览范围内，不意外跳到公开文章或其他空间。
- 返回后保留空间展开状态、当前节点、搜索范围和列表滚动位置。
- 空间树在大量节点下使用固定可滚动区域，不无限撑高页面。

### 场景 D：搜索到阅读再编辑

**前置条件：** 顶级文章和空间文章中存在相同关键词。

**操作：** 使用管理端岛式搜索，打开结果，进入编辑，再返回浏览。

**预期：**

- 搜索覆盖标题、摘要和正文，并清楚显示完整空间路径。
- 打开搜索时输入框清空；Esc 或取消后恢复进入搜索前的岛内文字。
- 点击页面其他区域关闭搜索结果，选择分类后不立即关闭分类菜单。
- 从阅读进入编辑时定位到同一篇文章；保存或取消后可回到原阅读上下文。

### 场景 E：共享阅读能力一致

**操作：** 分别通过公开弹层、公开独立页、管理端弹层、管理端独立页和私密预览链接打开同一篇文章。

**预期：**

- Markdown、表格、任务列表、代码高亮、语言标签、复制按钮、KaTeX、Mermaid、附件和目录表现一致。
- 主题切换、阅读进度、上一篇/下一篇、键盘操作和移动端布局一致。
- 管理端身份只改变数据权限和管理动作，不复制渲染实现。
- 草稿、空间文章和预览页不得进入搜索引擎，也不得进入公共缓存。

### 场景 F：移动端管理

**操作：** 在 390×844 视口完成浏览、搜索、打开文章、目录跳转、返回、进入编辑和空间导航。

**预期：**

- 岛式导航、搜索图标、底部管理导航、弹层和上一篇/下一篇不重叠、不越界。
- 阅读器使用页面可用高度，不被顶部工具栏或底部操作栏框死。
- 触控目标足够清晰，正文无需横向滚动；代码块和宽表格仅在自身区域横向滚动。

## 4. 实施阶段

### 阶段 0：生产环境收尾验收

这是下一项立即执行的任务，先验证，不改界面。

1. 使用现有专用测试草稿验证私密附件，并把一份测试附件绑定到既有公开 Markdown 示例文章以验证公开读取；不发布测试草稿、不修改公开文章正文。
2. 验证公开、管理员、私密预览和无权限四种读取路径。
3. 验证 MCP 的附件上传、列出、下载及审计回执。
4. 对首页、归档、普通文章、富内容文章和管理端登录页重新采集冷/暖缓存数据。
5. 记录 TTFB、FCP、LCP、CLS、请求数、JS/CSS 传输量和 Cloudflare 缓存状态。
6. 将生产结果补回 `2026-09-02-performance-optimization.md`，关闭已经解除的 R2 阻塞。

**退出条件：** 附件权限和缓存无错误，生产性能有可复现数据，未出现新的 5xx 或隐私泄漏。

### 阶段 1：锁定共享阅读契约

1. 为共享阅读器补充行为测试，覆盖公开、管理、空间和预览四种 scope。
2. 明确统一能力：文章加载、目录、阅读进度、翻页、主题、动画、键盘、附件和错误态。
3. 把权限差异限制在数据查询和操作栏，禁止在各页面复制阅读器 JSX/CSS。
4. 明确上一篇/下一篇的范围参数，防止空间之间串跳。

**退出条件：** 共享能力有自动测试保护，后续改造不会造成前后台表现分叉。

### 阶段 2：管理端浏览状态与导航

1. 将筛选条件、空间节点、搜索范围、弹层文章和滚动位置定义为统一浏览状态。
2. 在弹层打开、独立页跳转、编辑返回和浏览器前进/后退之间保持状态一致。
3. 完善可收起管理栏；桌面端保留内容宽度，移动端使用底部导航和临时空间抽屉。
4. 把管理动作收敛到轻量工具区，阅读中默认弱化，悬浮或聚焦时显示说明。
5. 补齐加载、空状态、错误、过期会话和无权限反馈。

**退出条件：** 场景 B、C、D 在桌面端完成，且公开页面视觉无变化。

### 阶段 3：移动端和交互细节

1. 逐项修复岛式导航、搜索、分类、目录、弹层、翻页和编辑入口的断点问题。
2. 统一弹层关闭规则：选择项不立即关闭；点击外部、Esc 或明确取消才关闭。
3. 统一阅读结束标记、上一篇/下一篇卡片和空间路径的移动表现。
4. 验证触控、软键盘、屏幕旋转和减少动态效果模式。

**退出条件：** 场景 F 全流程可用，无遮挡、越动和不可触达控件。

### 阶段 4：性能、可观测性与上线

1. 确保公开首屏不静态加载管理端、编辑器、Markdown 完整阅读器和 Mermaid 大包。
2. 确保管理端浏览不预加载 Vditor，进入编辑时才加载编辑器资源。
3. 保持现有 CSS 与动态阅读器构建预算，并为管理端新增可复现预算。
4. 增加关键请求的分层计时和错误日志，但不得记录正文、令牌、Cookie 或附件内容。
5. 完成类型检查、构建、lint、自动测试、Worker dry-run 和生产冒烟验证。
6. 小批次提交；每批部署后验证，出现权限或缓存回归时立即回滚 Worker 版本。

## 7. 风险与回滚

- **生产测试数据污染：** 使用明确命名的测试草稿；删除前单独确认，不把删除混入自动验证。
- **共享阅读器改动影响前台：** 先补行为测试，每个提交同时回归公开页面和管理端。
- **浏览状态过度复杂：** 只保存恢复体验必需的状态，不建立第二套全局状态框架。
- **缓存泄漏私密内容：** 私密路径默认 `no-store`，缓存优化必须先证明 scope 不含身份数据。
- **移动端为适配而重做布局：** 只调整断点、尺寸和层级，不改现有视觉语言。
- **R2 成本异常：** 保留 1 美元预算提醒，验证使用小文件，不进行批量迁移。

部署后保留上一个稳定 Worker Version ID。发生 5xx、登录异常、私密内容可见、附件越权或严重布局回归时，停止后续批次并回滚。

4. R2 网页端与 MCP 上传下载在生产环境可用，权限和缓存符合预期。
5. 公开页面视觉没有明显变化，首屏性能不低于当前生产版本。
6. 自动测试、构建、lint、dry-run 和线上冒烟全部通过。
7. 所有提交已审查、推送，计划中的生产数据与性能结果已更新。
